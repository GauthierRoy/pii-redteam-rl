| D20 | RL collapse guard, amends D18 (owner, 2026-11-14, after the long run `long-20261114-004948`) | The D18 reward let the attacker collapse onto one letter template (253/254 post-RL texts open with "Dear"). | D21 | Person judge in the RL reward, amends D18 (owner, 2026-11-14/15, after `pilot-opening-20261114-124322`) | With the D20 guard the attacker found another exploit around step 300: it uses the requested name as a place or brand ("the nearest Mulaton store", "the El Bez clinic"). | D23 | Log-odds detector reward for the attack on the retrained detector (owner, 2026-11-17, after `m10-attack-retrained-20261115-203246`) | Against the retrained detector the plain reward 1 - p stayed flat for 400 steps: median p 0.9998 throughout, mean valid reward 0.007, within-group std of valid rewards 0.011, so the only real reward gaps were valid vs invalid and the attacker learned validity (0.78 -> 0.97), not evasion. New optional scale `reward.detector_score: {kind: log_odds, span}`: reward = clip(1 + log((1-p)/p) / span, 0, 1); with span 10, p = 0.9998 -> 0.15, 0.99 -> 0.54, 0.9 -> 0.78, p <= 0.5 (a miss) -> 1. On that run's 11,967 valid texts it raises the within-group std to 0.072 and the mean to 0.156. Note: -log(p) would not help, since near p = 1 it equals 1 - p; the scale must use log(1 - p). Invalid texts keep -1; the guard factor and the person judge are unchanged. One 400-step Modal run (`configs/m10_attack_logodds_modal.yaml`) tests whether the detector probability starts to fall; more steps only if it does. Absent key = 1 - p, so earlier configs are unchanged. | Pilot done (`m10-attack-logodds-20261117-212849`): signal appeared but was spent on a label exploit; see D24 |

| D25 | Read every detector as PERSON / not-PERSON; B/I tags were a design error (owner, 2026-11-18) | The owner pointed out that B-PERSON / I-PERSON makes no sense for this project: one entity type, used for redaction, one requested name per text. Measured on AI4Privacy (final eval excluded): 35 touching PERSON-span pairs among 18,253 spans on the train side (0.19%), 15 among 5,031 on dev, mostly a first and last name split by a line break. The B/I split cost one RL run (D24 exploit). Recorded as limitation L1 in `docs/LIMITATIONS.md`. Earlier numbers stay as recorded; post-D25 comparisons are re-scored. | Decided; implemented |

## Settled implementation choices (M01, reversible)

- R01: stdlib + pyyaml runtime at M01; heavy ML deps deferred to their pilot milestones.
- R02: `grpo_compat` reused from `../rl` with lazy `trl` import (see `docs/REUSE_AUDIT.md`).
- R03: Offsets are Python str indices, end-exclusive; recorded in `validation.py`.
- R04: Invalid reward total (-1.0) sits below the valid [0, 1] range; components logged separately.
- R05: Split roles locked 2026-10-04 (M02.3): seeded final-eval carve (1,000 train-file rows,
  sha256 in `docs/DATA_CARD.md`); validation file stays development-only; exact-text
  duplicates banned, template reuse measured (found none at skeleton level).
- R06: Name pools (M02.4): generation requests draw only from `train_side_pool`
  (16,403 values); 200 held-out names are final-eval-unique and reserved for M04 paired tests;
  exact-match disjoint from the pool, substring overlap (19/200) recorded as a limitation.
- R07: Requestable-name filter (owner-approved 2026-10-04): pool values that are
  dataset artifacts (digits, `@`, pipe/slash fragments, single initials; 74/16,403 =
  0.45%) are excluded from generation request pools. Enforced in
  `load_person_name_pool` (`is_requestable_name`), so all request paths reject them;
  detector training texts are NOT filtered.
- R08: target detector training-data gates (owner, 2026-10-13, M07b.2 precondition): the
  extra-person check must NOT rely on the base detector (D13: ~50% miss rate on short
  conversational names). Independent checker = spaCy `en_core_web_sm` NER OR a
  small LLM judge (Qwen3.5-2B, greedy yes/no), rejecting any row with an extra
  person mention; person-sense check (name = a person, not a place/object/entry)
  via the same LLM judge, validated by a manual audit of 50 rows. Rejection
  rates reported with the M07b results (`docs/PROMPT_V2_RESULTS.md`).
